# Instances that render a Lean module NO verdict grips.
#
# Until 2026-08-18 this list lived as a comment inside
# `hypothesis-binding-attestations.txt` — "listed so a later sweep does not
# re-discover them as news. They are NOT checked." That was honest and it was
# not enough. A class nothing runs on can only be ENTERED: an instance that
# becomes bindable stays declined forever, and an instance whose module degrades
# is never looked at. Both costs were real, and the second one had already been
# paid: `cvc5__cli__regress0__bv__holes__extract-concat.smt2` sat in this list
# rendering a SELF-REFUTING module — eleven reflexive `Iff`s under one negation,
# so Lean's `False` followed from that one axiom with the `.smt2` file never
# consulted — and no run in this repository ever touched it. It is gone from the
# list below because its route now declines.
#
# So this is a pin now, and it is TWO-SIDED like its four neighbours. Each
# instance must
#
#   * render a module (a route that stops rendering one fails the run, loudly,
#     rather than silently shrinking the denominator), and
#   * FAIL the bound, structural, anchored and attestation checks, each named.
#
# The only way a declined pin can fail is by an instance getting BETTER. That is
# exactly the direction a prose list cannot see, and it is the direction this
# repository has twice discovered by measurement rather than by a check: 95
# modules were recorded as content-free while they were structural all along,
# and 66 were recorded as merely `structural` while their queries asserted the
# disequality outright.
#
# WHAT IS HERE, and why each is out of reach. Measured 2026-08-18.
#
#   16  QUANTIFIED LIA/BV. The rendered hypothesis is a pi-type
#       `((x0 : Int) -> … Or/Not/Iff …)` or an `Exists`/`Not Exists` — a shape no
#       linear-atom parser models, and the atom pool the binder matches against
#       is a set of ground linear atoms. Binding these needs a checker for
#       quantified statements, which is a different object.
#       (The prose list this replaces said 13 quantified and 7 ground. Measured
#       by path, it is 16 under `quantified/` and 4 that are not — the two
#       counts were of different things and neither said which.)
#
#    3  GROUND, and the hypothesis is the OUTPUT OF A SOLVER STEP rather than a
#       transcription of any `(assert …)` line, so there is no assertion for it
#       to bind to:
#         * `constarr2.smt2` renders one axiom, `Eq.{1} Int Int.zero Int.one`.
#           The query says `all1 = const 1`, `all2 = const 2`, `all1 = all2`; the
#           `0 = 1` is what the Diophantine step DERIVED from reading those
#           arrays at an index. It is a closed proposition and it mentions no
#           query symbol at all. NOT self-refuting — nothing in the module's own
#           prelude proves `Int.zero = Int.one` without it — but its Lean
#           evidence corroborates as little as an attestation's does, and it is
#           counted here rather than there because the attestation class means a
#           specific opaque-skeleton SHAPE, which this is not.
#         * the two `bug593.smt2` rows (QF_UF and QF_UFBV, the same query under
#           two logics) render a `FiniteDomainPigeonhole` refutation whose three
#           hypotheses are `¬(f a = f b)` over Bool-typed arguments. The query's
#           arguments are `(g x)`, `(g y)`, `(g z)` — APPLICATIONS — and the
#           emitter collapses each into one opaque `fd_arg_N : Bool`. This is the
#           same emitter defect `ArrayAxiom` had on 2026-08-18, when 89 modules
#           stopped collapsing whole terms into one constant and became
#           `structural`. Nothing about the certificate prevents it here; the
#           argument's structure is simply not rendered. That is the next
#           concrete move out of this file.
#
#    1  `extract-concat` — REMOVED, see the header. Its route declines.

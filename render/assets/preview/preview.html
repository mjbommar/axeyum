reading level

A rendered document here is a checker output, not prose about one. That distinction is the whole design, and it is visible on this page: nothing below carries a green badge because a person decided it deserved one. Each badge is the epistemic_status field of a file in artifacts/facts/, each replay command is that file's checker_command, and a claim that arrived without evidence renders saying so.

What follows is one connected component of the ledger's dependency graph — the naturals, the integers, the rationals built over them, and Euclid's theorem at the bottom of the chain — with two deliberately unrelated facts alongside it for contrast. Read it at summary to see only the argument, at full for the evidence, at forensic for everything the ledger carries.

Four facts, four kinds of standing

The ledger keeps two status axes on purpose: what this system established, and what mathematics knows. They are different questions, and their disagreement in our favour is a result rather than a bookkeeping error. The four cards below are one of each interesting case.

There is no largest prime

herePROVEDliteraturePROVED

F:nat-exists-prime-gt

For every natural number n there is a prime p with n < p. Equivalently, there are infinitely many primes.

formal statement · lean4 · Nat

theorem Nat.exists_prime_gt : ((n : AxNat) -> Exists.{1} AxNat (fun (p : AxNat) => And (AxNat.lt n p) (And (AxNat.le (AxNat.succ (AxNat.succ AxNat.zero)) p) ((d : AxNat) -> ((hd : AxNat.dvd d p) -> Or (Eq.{1} AxNat d (AxNat.succ AxNat.zero)) (Eq.{1} AxNat d p))))))

proof route kernel-lean · axiom footprint empty (axiom-free)

evidence

  • kernel-termkernel-Nat.exists_prime_gt

    For every natural number n there is a prime p with n < p.

    cargo run -q -p axeyum-lean-kernel --example nat_theorem_inventory -- exists_prime_gt 2>/dev/null | grep -qxF 'Nat.exists_prime_gt 3 ((x0 : AxNat) -> Exists.{1} AxNat (fun (x1 : AxNat) => And (AxNat.lt x0 x1) (And (AxNat.le (AxNat.succ (AxNat.succ AxNat.zero)) x1) (((x2 : AxNat) -> ((x3 : AxNat.dvd x2 x1) -> Or (Eq.{1} AxNat x2 (AxNat.succ AxNat.zero)) (Eq.{1} AxNat x2 x1)))))))'
    why this counts

    build_nat_prelude admits this through the trusted Kernel::add_declaration gate, which re-checks the proof term against the stated type. Euclid's argument, done over N with no subtraction: take m = n! + 1, which is >= 2 because 1 <= n! (one_le_factorial), and let q be a prime dividing it (exists_prime_dvd). If q <= n then dvd_factorial_of_le gives q | n!, and with q | n!+1 dvd_add_right_cancel_of_pos yields q | 1, refuted by not_dvd_one_of_two_le. So n <= q, and the n = q case falls to the same contradiction after transporting n <= n along the equality, leaving n < q. The command matches the FULL RENDERED TYPE (grep -qxF), not the theorem name: lane nat-prime-divisor measured that a name-only checker survives a weakened statement — spelling a primality bound 1 <= p instead of 2 <= p still type-checks, still admits, and is satisfied by p = 1. The kernel cannot see a weaker statement; only the type can.

    theorem_axiom_footprint reports nat Nat.exists_prime_gt 0 and integer Nat.exists_prime_gt 0. nat_axiom_inventory bounds it by enumerating the whole trusted surface: a theorem cannot depend on a trusted declaration the environment does not contain. Counting Declaration::Axiom alone would not suffice — Opaque has no proof body and Quotient admits Quot.sound — so all three kinds are covered.

note

open here means NOT ESTABLISHED IN THIS LEDGER; it is not mathematically open, Euclid settled it. It is recorded because it is a live target rather than a curiosity: the prelude already carries Nat.not_dvd_one_add_mul_of_two_le, which is exactly the step no a >= 2 divides 1 + a*t — the contradiction at the end of Euclid's argument. 2026-08-17: BOTH missing ingredients have now landed and this fact is one slice from closing. Nat.factorial is declared (computation rules definitional, like Nat.pow) together with Nat.dvd_factorial_of_le : (d n : AxNat) -> AxNat.le 1 d -> AxNat.le d n -> AxNat.dvd d (AxNat.factorial n), so the number that every positive d <= n divides exists in the kernel and 1 + n! is a witness with no divisor in [2, n]. The second ingredient is F:nat-exists-prime-dvd: Nat.exists_prime_dvd : (m : AxNat) -> AxNat.le 2 m -> Exists p, (2 <= p AND forall d, d | p -> d = 1 OR d = p) AND p | m, admitted axiom-free. Note it did NOT go through lt_well_founded as this note previously predicted — strong induction on m would have to DECIDE primality of m, a bounded universal quantification whose constructive decision is itself a bounded search, so the search (Nat.least_divisor_search) is done directly by ordinary Nat.rec on the bound and returns the LEAST divisor >= 2, which is prime for free. WHAT REMAINS is exactly two steps, both small: (1) 1 <= Nat.factorial n — factorial is positive, by induction with one_le_mul at the successor — which is what makes 2 <= 1 + n! and so lets exists_prime_dvd be applied to it at all; and (2) the assembly. The assembly: take p prime with p | 1 + n!; if p <= n then dvd_factorial_of_le gives p | n!, add_comm reshapes 1 + n! to n! + 1, dvd_add_right_cancel_of_pos yields p | 1, and not_dvd_one_of_two_le refutes it; so le_total leaves n <= p, and lt_or_eq_of_le turns that into n < p once n = p is ruled out by the same contradiction. Every lemma named in that paragraph is already admitted axiom-free. formal.statement is written in the SAME core rendering the kernel emits for its own theorems, and uses ONLY symbols build_nat_prelude actually declares (checked against the 119-theorem inventory dumped on 2026-08-14), so it can be dispatched without inventing vocabulary. Primality is spelled out inline because the prelude has no Prime predicate. Binders carry readable names rather than the kernel's x0, x1, ...; that is a pretty-printing difference only, and any admitted proof would render with positional names.

Bezout's identity holds for the natural gcd

herePROVEDliteraturePROVED

F:nat-gcd-bezout

For all natural numbers m and n there exist natural numbers mp, mn, np, nn with gcd(m, n) + m*mn + n*nn = m*mp + n*np. This is Bezout's identity in balanced form: the usual gcd(m,n) = m*x + n*y with integer x, y, rearranged so both sides are natural numbers.

formal statement · lean4 · Nat

theorem Nat.gcd_bezout : ((x0 : AxNat) -> ((x1 : AxNat) -> AxNat.bezout x0 x1 (AxNat.gcd x0 x1)))

note

AxNat.bezout m n g abbreviates the balanced form. The balancing is forced: the naturals have no negatives, so a Bezout coefficient that would be negative is moved to the other side of the equation instead. formal.statement is the type the kernel admitted, taken verbatim from Kernel::render_lean over the environment build_nat_prelude produces; it was not transcribed by hand. The sort renders as AxNat (the prelude's own inductive) while declarations are rooted at Nat.

fp8 E5M2 addition under roundNearestTiesToEven is associative

hereREFUTEDliteratureREFUTED

F:fp8-add-not-associative

Let F be the IEEE-754-conformant 8-bit format OCP fp8 E5M2, SMT-LIB (_ FloatingPoint 5 3), and let RNE denote roundNearestTiesToEven. For all values a, b, c of F: fp.add(RNE, fp.add(RNE, a, b), c) equals fp.add(RNE, a, fp.add(RNE, b, c)), where equality is SMT-LIB = on the FloatingPoint sort. THIS PROPOSITION IS FALSE. The fact is recorded with status refuted and carries a concrete counterexample triple, together with the exact number of triples at which it fails.

formal statement · smtlib2 · QF_FP

(assert (= (fp.add RNE (fp.add RNE a b) c) (fp.add RNE a (fp.add RNE b c))))

proof route search-certificate · rests on ieee754-2019-arithmetic-semantics-for-the-OCP-fp8-E5M2-layout, rounding-mode-roundNearestTiesToEven-for-the-headline-witness, smtlib2-floatingpoint-sort-equality-one-nan-value-signed-zeros-distinct, the-witness-replay-semantics-of-axeyum-Evidence::check-and-of-rustc_apfloat

    why this counts

    Ran 2026-08-14: sat, 2ms.     cargo run --release -q -p axeyum-fp --example kernel_equivalence -- assoc

    checked by rustc_apfloat-0.2.3-llvm-apfloat-exhaustive-enumeration

    artifact crates/axeyum-fp/examples/kernel_equivalence.rs

    why this counts

    Ran 2026-08-14, 2.2s. Independent of axeyum's bit-blaster, CNF encoder and SAT core: rustc_apfloat 0.2.3 (LLVM APFloat), comparing SMT-LIB value classes. The failure count is mode-dependent and was measured for all five SMT-LIB rounding modes: RNE 427036, RNA 419652, RTP 4825040, RTN 4825040, RTZ 5375600 — of 16777216 triples each. The directed modes fail an order of magnitude more often, and RTP/RTN fail equally often, which is the sign symmetry of the format. The first witness in enumeration order is the same triple under every mode. The binary exits non-zero if the claim ever stops failing.

note

WHY A REFUTATION IS THE VALUABLE RESULT HERE. Every reduction kernel, every tensor-parallel all-reduce and every reordering optimizer relies on being allowed to re-bracket a sum. This fact says precisely how often that is wrong at fp8 E5M2: 427036 of 16777216 triples under RNE, and 5375600 — nearly a third — under round-toward-zero. That is a measured density with a named witness, not an aphorism.

THE FINDING ABOUT THE ORACLES. This claim could not be cross-checked against either industrial FP solver, for two DIFFERENT reasons, and both were measured on 2026-08-14 rather than assumed: * z3 4.13.3 returns unknown with (:reason-unknown "addition/subtract with ebits > sbits not supported"). E5M2 has 5 exponent bits and 3 significand bits, so every fp8 addition query is outside its fpa2bv tactic. * bitwuzla 0.9.1 errors out: "Unsupported experimental floating-point format (non-experimental: Float16, Float32, Float64, Float128)". The --fpexp escape named in that message is a BUILD option, not a runtime flag — passing it to the binary is rejected as an invalid option, so this build cannot be talked into it. So at exactly the width where a claim can be settled by brute force, the two solvers a practitioner would reach for decline. axeyum decides it, and the LLVM-APFloat enumeration is what independently confirms the answer. Note the complementary gap in the other direction: axeyum REFUSES fp8 E4M3, correctly, because E4M3 has no infinities and an all-ones NaN and is therefore not an IEEE format — arithmetic_format_supported gates it out, while z3 accepts (_ FloatingPoint 4 4) happily.

ROUTE. search-certificate: the settlement is a replayable witness, matching the precedent of F:affirming-the-consequent. Refuting a universally quantified claim costs one triple; establishing one costs the whole space — and here we paid both, because the enumeration also gives the density.

The argument for the bottom node

This block carries no provenance, which is the schema's signal that a person wrote it: it is the human argument, not a captured machine trace. The machine's version of it is the proof term the kernel checked, and the card above is where that is recorded.

or press j / k with the list focused
  1. suppose
    n : Nat
    → consider N = n! + 1
    Any prime dividing N is larger than n, if one exists.
  2. apply
    N >= 2
    → N has a prime divisor p
    This is F:nat-exists-prime-dvd, one layer up in the graph.
  3. suppose for contradiction
    p <= n
    → p divides n!
    p is one of the factors of n!.
  4. apply
    p | n! and p | n! + 1
    → p | 1
    This is F:nat-dvd-add, which is why that node is an ancestor of this one and not merely nearby.
  5. conclude
    p | 1 and p prime
    → contradiction; so p > n
    There is no largest prime.

## Centrally-enforced coverage (NOT the same measurement)

The columns above are PER-FACT EVIDENCE: this fact's own record
exercises the protection. A gate that enforces the same protection on
every merge, for facts that cite nothing, moves none of them. The two
are different questions and neither dominates -- per-fact evidence is
self-describing and survives the fact being copied elsewhere; central
coverage is stronger in practice and far cheaper. ADR-0795.

A gate earns a column here only by publishing, machine-readably, the
PER-FACT SET it reached. A headline number confers nothing on any
member, and `protection_count` above deliberately excludes these: a
fact is not better protected because somebody else measured it.

Gates that enforce a protection this census names and publish NO

row is a finding about the GATE, not about the facts; the missing
column is what the gate would have to emit (ADR-0795).

## Thin spots

- 320 / 2487 proved facts hold two protections or fewer.
- 265 / 2487 have no discriminating checker naming their own subject, where the subject is taken only from an EXPLICIT
  `formal.kernel_theorem` / `kernel_declaration` binding.
- of those, 0 would gain one if the ledger's regex
  fallback (`theorem_of`, whose own docstring calls it "demonstrably NOT
  reliable in general") were trusted. That gap is the size of the
  ledger's unbound-subject debt, not a protection.
- 0 / 2487 have no `formal.statement` drift pin.
- 2478 / 2487 have no independent Lean replay.
- 2296 / 2487 carry no semantic-falsification evidence row.
- 2472 / 2487 name no mutation or negative control.
- 2412 / 2487 have no PER-THEOREM axiom footprint check; their footprint evidence is the prelude-wide sweep.
- 55 / 2487 have NO checker of their own: every command they cite is shared with another fact.
- 17 / 2487 cite no `checker_command` at all.
- 2237 / 2487 carry an evidence row listing two or more named `checkers`, and 1461 of those name the PRODUCING run as one of
  them. The production is not a re-derivation of itself, so those rows
  are one check and one re-list, not two independent checks —
  `validate-facts.py` counts them toward its "re-derived by 2+
  independent checkers" line.
- 2173 evidence rows across 2173 facts declare a semantic `kind` (`exhaustive-enumeration` / `instance-pin`) while their
  `supports` records an axiom footprint. Nothing was enumerated. Read at
  face value the `kind` enum would over-report semantic falsification by
  2173 rows, so this census reads `supports`, not `kind`.

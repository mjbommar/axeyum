# Runnable Examples

This page inventories every Cargo example checked into the workspace. It keeps
three different things separate:

- **learning examples** are safe starting points and print to standard output;
- **artifact generators** intentionally create or refresh reports and require a
  reviewed output path or clean-tree check; and
- **maintainer diagnostics** are narrow measurement probes, not stable product
  interfaces.

An example being present under `examples/` means Cargo builds it under the
appropriate all-target gate. It does not make its arguments, output schema, or
performance a public compatibility promise. For library APIs, use
[Public API](public-api.md); for the supported SMT-LIB boundary, use
[SMT-LIB support](smtlib-support.md).

## Start with these

These commands have no external solver requirement and do not intentionally
write tracked files:

```sh
cargo run -p axeyum-solver --features full --example first_smtlib_query
cargo run -p axeyum-cas --example cas_tour
cargo run -p axeyum-cas --example certified_calculus
cargo run -p axeyum-bench --example curriculum_demo
```

| [`geometry_portfolio`](../../crates/axeyum-solver/examples/geometry_portfolio.rs) | `axeyum-solver` | Compares the specialized LRA and incomplete NRA routes on the same small geometry goals. Requires `--features full`; timings are measurements, not API guarantees. |

```sh

cargo run --release -p axeyum-bench --example scenario_pipeline_report
cargo run --release -p axeyum-bench --example scenario_scaling
```

| [`wf_recursion_decline_probe`](../../crates/axeyum-lean-import/examples/wf_recursion_decline_probe.rs) | `<export.ndjson>` | Reduces a `TypeMismatch` decline to the smallest pair of terms the kernel refuses to identify, *inside the staging environment that refused them*. `lean4export_census` can only report two arena indices, and those cannot be printed after the fact because the staging kernel is dropped with the census; this re-runs the same records through the same gate and walks the two terms down — whnf, spine, congruence, binders — printing the first pair at each depth the kernel calls not definitionally equal. Written for `Nat.bitwise._unary`, which now prints `PROBE\|no kernel decline`; use `Nat.Linear.Poly.denote_reverse` for a stream that still declines. |

| [`creal_shape_probe`](../../crates/axeyum-lean-kernel/examples/creal_shape_probe.rs) | no arguments | Prices ℝ before building it (ADR-0468). | [`creal_setoid_witness`](../../crates/axeyum-lean-kernel/examples/creal_setoid_witness.rs) | no arguments | ℝ **constructed**, and **all 22 ordered-commutative-ring laws proved over it** at a measured trusted surface of **0** — a Bishop setoid of regular ℚ-sequences (ADR-0468 phase R2, complete). Where [`creal_shape_probe`](../../crates/axeyum-lean-kernel/examples/creal_shape_probe.rs) priced the carrier parametrically before ℚ had an order, this is the real thing over the constructed `Rat`. The exit status depends on eight findings, and the last six are what stop a green light being vacuous: every declaration checked and footprint-empty; the whole trusted surface still empty; `CReal.ofRat` present, so `CReal.Regular` has a **solution** and the carrier is not the empty type (every law would otherwise hold, footprint-free, of nothing); `CReal.Equiv.not_zero_one` present, so `Equiv` is not the **total** relation, which is also an equivalence relation; `CReal.not_le_one_zero`, without which all three `le` laws hold footprint-free of the relation that relates every pair; `CReal.zero_lt_one` **plus** `CReal.lt_irrefl`, because six of the seven strict-order laws only CONSUME a `lt` and so all hold, footprint-free, of the EMPTY relation; `CReal.ofRat_mul` **plus** `CReal.not_equiv_mul_one_one_zero`, because `mul_zero`, `mul_comm` and `sq_nonneg` all hold, footprint-free, of the product `fun _ _ => zero` — `ofRat_mul` pins the OPERATION on the embedded ℚ rather than asserting a property of it; and finally `CRealPrelude::ordered_ring_laws` naming **22 distinct** footprint-empty theorems, which is where the headline count is read from and nowhere else. Verified by mutation: deleting any one witness, or any one law, leaves every other row green and still exits 1. Thirteen of the 22 are the `Real` package's statements **verbatim**; the other nine mention `Eq` there and are stated over `CReal.Equiv` here, because `Eq CReal` is not the equality of real numbers — making that substitution good is phase R4, which this example does not claim. |
| [`complex_ring_witness`](../../crates/axeyum-lean-kernel/examples/complex_ring_witness.rs) | no arguments | ℂ **constructed** over the constructed ℝ, and **all 9 commutative-ring laws proved over it** at a measured trusted surface of **0** — a pair of `CReal`s under the componentwise *defined* equality `Complex.Equiv`, so no quotient is taken at either level and `Quot.sound` is never needed (ADR-0472). The exit status depends on seven findings, and the last three are what stop a green light being vacuous or degenerate: every named declaration checked and footprint-empty; the whole trusted surface still empty; `ComplexPrelude::ring_laws` naming **9 distinct** footprint-empty theorems, which is where the headline count is read from and nowhere else; `Complex.ofReal` present, so the carrier is not the empty type; `Complex.Equiv.not_zero_one` **plus** `Complex.Equiv.not_zero_I`, because the first refuses the total relation and only the second refuses one that ignores the imaginary component entirely — under which ℂ would be ℝ; `Complex.ofReal_mul` **plus** `Complex.I_sq`, because `mul_comm`, `mul_zero` and `left_distrib` all hold, footprint-free, of `fun _ _ => zero`, and `ofReal_mul` cannot pin `I` since `I` is not in the image of `ofReal`; and finally `Complex.no_compatible_order` present **and** `Complex.le`/`Complex.lt` absent from the environment. That last pair is the point: the 13 order laws of the `Real` package are missing here because they are **refuted**, not deferred — the theorem quantifies over both relations and derives `False` from seven of them with `I` as the witness — and an omission looks identical to a refutation unless the witness checks both halves. |
| [`lean_hypothesis_binding_dump`](../../crates/axeyum-solver/examples/lean_hypothesis_binding_dump.rs) | `<file.smt2>` | Deliberately dumb: parses a query, solves it, renders the Lean module, and prints the source assertions beside the module's `axeyum.reconstruct.*.hyp._N` axioms — making no judgement about whether they correspond. `scripts/check-lra-hypothesis-binding.py` re-parses and re-normalizes BOTH sides in Python, sharing no code with this dumper or with `axeyum-smtlib`, so the renderer's own notion of "same constraint" cannot launder a mis-transcription. Splitting it this way is the point: the thing being checked must not also be the judge. |
| [`characterization_status`](../../crates/axeyum-lean-kernel/examples/characterization_status.rs) | no arguments | Prints whether our `Nat` and `Int` are provably *the* naturals and integers, rather than merely axiom-free inductive types with those names. | [`creal_model_witness`](../../crates/axeyum-lean-kernel/examples/creal_model_witness.rs) | no arguments | The same table as [`arith_model_witness`](../../crates/axeyum-lean-kernel/examples/arith_model_witness.rs), at a carrier that **is** ℝ (ADR-0468 phase R4). Each witness `Real.CRealModel.<law>` is a theorem whose type is the `Real` axiom **as it stands in the environment** with the eight carrier/operation constants substituted and the partial application `Eq Real` read as `CReal.Equiv`, proved by the corresponding `CReal` theorem and type-checked by the kernel at admission — so an axiom `CReal` does not satisfy makes the build FAIL rather than dropping a row. The exit status also depends on the population coming from the environment (a 31st `Real` axiom is a shortfall, not a tidier count) and on the **seven discrimination witnesses**, because 22 empty footprints look identical over an empty carrier, a total relation, an empty relation or a constant-zero product; presence is asserted before any footprint is read, since `axiom_footprint` of an interned-but-undeclared name is empty. Verified by mutation: disabling the `Eq Real` rewrite makes the kernel refuse the model outright (`DeclarationValueMismatch`), dropping one law fails the coverage check, an undeclared guard name fails the vacuity check, and falsifying the restated flag kills **exactly one** unit test. This discharges ADR-0456's "`Int` is not ℝ" caveat; it does **not** give `Eq CReal` as real-number equality, which is what would cost `Quot.sound`. |

Nothing is reported without a Chandra–Merlin homomorphism that `check_homomorphism` has already replayed, and a `sat` model is additionally replayed against its encoding by the IR evaluator. The routes must agree; disagreement is a failure, not a tie-break. The complete-evaluation leg is what makes a *negative* answer an exhibited counterexample rather than a search that gave up. |
| [`db_design_certify`](../../crates/axeyum-bench/examples/db_design_certify.rs) | `<file.dbd> [--expect-checks N] [--verify-formal <file.smt2>] [--timeout SECONDS]` | Executes the `expect …` lines a committed relational-schema instance pins — functional-dependency implication, keys, BCNF/3NF, lossless join, dependency preservation — and refuses to report any answer without a certificate an independent checker has already replayed: an Armstrong derivation, a decoded two-row counterexample relation, or a replayed chase trace. Implication is decided twice by routes sharing no code (the attribute-closure fixpoint and the solver on a Boolean Horn encoding) and they must agree. It fails if the file pins nothing, if an expectation is unmet, or if fewer obligations ran than the file declares — a checker that exits `0` on completion alone checks nothing. |


## Artifact generators

These examples can write JSON, Markdown, DIMACS, or committed consumer reports.
Use scratch output paths first. If a command intentionally refreshes a tracked
artifact, start from a clean tree and review the complete diff.

The generic release-mode form is:

```sh
cargo run --release -p axeyum-bench --example <name> -- <arguments>
```

Do not retain a measurement merely because the command exited successfully.
Apply the [benchmark artifact contract](../contributor-guide/benchmark-artifacts.md):
bind the corpus and solver revision, keep limits/configuration, check verdict
agreement and replay, and separate diagnostics from credited results.

## Inventory and validation

The authoritative target list comes from Cargo metadata, including required
features:

```sh
cargo metadata --no-deps --format-version 1 |
  jq -r '.packages[] as $p | $p.targets[] |
    select(.kind | index("example")) |
    [$p.name, .name, ((.["required-features"] // []) | join(","))] | @tsv' |
  sort
```

`cargo test --workspace --all-targets --all-features --no-run` compiles the
complete target population without executing artifact-producing `main`
functions. The repository's full pre-merge and hosted CI gates include
all-target compilation; a focused documentation edit should not rerun every
measurement example.

# Notes: 360-creal-supon

Detail moved out of [`../status/360-creal-supon.md`](../status/360-creal-supon.md) so the
lane-status block stays inside the per-lane ceiling. Nothing here was
deleted; it was moved.

1. **The upper-bound law**, `∀ x, le a x → le x b → le (F x) (supOn F a b hab u)`.
   An arbitrary `x` is not a mesh point, so this needs `x` placed within one
   cell of some mesh point, then `CReal.max_range_ub` at that index, then a
   limit passage through `supSeq_converges_supOn`. The mesh index for `x` is
   the one place a `bucketIndex`-style lookup still looks necessary — but the
   conclusion is `Prop`, so rung 6's own trick (make the index an `Exists`
   witness the induction re-eliminates) should apply again.
   `meshPoint_near_coarse` is the wrong shape only because it relates two
   MESHES rather than a point to a mesh.
2. **The approximate least-upper-bound law**: for every `eps > 0` there is a
   point of `[a, b]` at which `F` exceeds `supOn − eps`. **This must stay
   approximate.** Its exact form is what `CReal.evt_attained_max_decides_sign`
   refutes; an approximate row 1 beside an exact row 2 is ADR-0603's grading
   working correctly, not a gap.

## Hypotheses, stated honestly

`supOn` takes `le a b` and a `UniformlyContinuousOn F a b` witness. The second
carries a MODULUS as data — the constructive substitute for "continuous on a
compact set", which no constructive development derives from pointwise
continuity. There is **no** Archimedean hypothesis and no positivity side
condition: the interval width is read off `CReal.bound`, a total computable
projection, inside `CReal.mesh_le_of_ge`.

## Where the prior plan had drifted

`supremum.rs`'s module doc is now marked stale from its "what this file lands"
heading, with a new section recording all of this. Its account of what LANDED
was reliable every time it was checked; its account of what REMAINED oversized
the work three times, all in the same direction:

1. **No telescope is needed, and neither is the "double telescope".**
   `meshMax_le_add_of_step_close` is already depth-uniform, so the estimate at
   `k' ≥ k` is ONE application and the number of intervening doublings never
   enters.
2. **Rung 5's schedule was missing the interval WIDTH.** `expOfModulus`
   schedules the modulus only; the mesh width is `(b−a)/2^j`, so without a
   width term the construction is correct only on intervals of width ≤ 1.
3. **`CReal.mesh_le_of_ge` already existed** and is exactly the Archimedean
   rescaling needed — in `integral.rs`, filed under its first consumer, with a
   left-hand side syntactically identical to `supremum.rs`'s own `mesh_delta`.
   `examples/shape_search` found it in one query; a name search would not have.

One undocumented rung had also landed since the plan was last written:
`CReal.meshLevelCount_pow`.

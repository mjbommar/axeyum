# Lane: simp-1 — the third producer: rewrite-chain `simp` for the kernel

<!-- plan-section: lane-status -->

**Your lane's block (`DONE for this session`, simp-1, 2026-09-03).** Landed
`crate::simp` — the third tactic-layer producer (ADR-1586, beside
`linarith`/ADR-1576 and `ring`/ADR-1580/ADR-1582): an oriented rewrite set
matched first-order, outermost-first, against a goal's own `ExprId` graph,
rewritten to a `MAX_STEPS = 32` fixed point per side, emitted as a
congr-lifted `Eq.trans`/`Eq.symm` chain and kernel-checked. No kernel
`Pi`-type introspection — a rule's pattern is a stateless `build` closure
over fresh pattern variables, reusing `ring::nat::prove_eq_at`'s "prove
generically, apply concretely" convention directly.

ℕ (`crates/axeyum-lean-kernel/src/simp/nat.rs`): 12 default rules
(add_zero/zero_add/mul_zero/zero_mul/mul_one/one_mul/pred_succ/sub_zero/
sub_self/succ_add/add_succ/succ_mul). **11** retirement targets landed (10
in the first pass, an 11th found and landed after re-checking a claim I
almost got wrong — see below), with a triplicated shape among them
(`two_mul_eq_add`/`mul_two_eq_add_self`/`eisenstein_floor_min_free::two_mul`,
all the same identity) and a duplicated pair (`one_add_eq_succ` at two call
sites) — see ADR-1586 for the list and line spans. 20 tests (11 targets + 3
NoProgress + 4 corrupted-chain + 1 BudgetExceeded). Cost (`--release`,
`--example simp_cost`): 0.21–0.53 ms search+emit, 0.28–0.63 ms with kernel
recheck, 200 emissions/shape.

ℤ (`crates/axeyum-lean-kernel/src/simp/int.rs`, non-generic over `IntDev`,
mirroring `ring::int`'s own choice): 10 default rules. Only 3 retirement
targets landed (`add_left_neg`, `zero_mul_eq_zero`, `zero_add`), not the 5
the brief scoped — **a measured, sized negative**, not a shortfall: ℤ has no
`zero_add`/`zero_mul`, so a goal needing the reversed argument order must
route through `add_comm`/`mul_comm` as a caller-supplied extra, and that is
only confluence-safe when the goal's post-annihilation fixed point has no
`add`/`mul` structure left for comm to keep re-swapping. `neg_mul`-shaped
goals looked identical in shape and were NOT reachable — tried, and
confirmed `Decline::BudgetExceeded` by actually running it (pinned as a test:
`a_neg_mul_shaped_goal_is_not_a_safe_retirement_target`), not inferred from
the shape alone. 12 tests.

`List` (deliverable 5's other half): **scoped, researched, NOT built.** Two
independently-sufficient reasons, both in ADR-1586 §4: (a) `list_prelude`
has no `NatOps`/`IntDev`-style trait — `ops.rs`'s `congr_of` takes explicit
`level`/`ty` argument PAIRS (domain and codomain can differ, e.g.
`List.length`), and every call site hand-numbers its own free-variable ids
from a reserved literal block instead of a `fresh_fvar()` counter, so this
is a genuinely different design (a `Ctx` struct, not a generic `D` param),
not a mechanical port; (b) more importantly, `grep -rn
"append_nil\|append_assoc\|reverse_append\|reverse_reverse"` across
`list_prelude/bridge.rs`/`perm.rs`/their submodules returns **zero** matches
outside the laws' own declarations in `theorems.rs` — there is currently no
retirement population to point a `simp::list` engine at. Building it
speculatively first would be the same unexercised-capability risk ADR-1580
already declined for `sort_factors`. The design sketch is in ADR-1586 §4 for
whichever lane picks this up once a real call site exists.

**A self-correction worth recording**: I first wrote (in a draft of this
note) that `eisenstein_floor_min_free.rs::two_mul` — a THIRD hand-written
copy of the same `Eq (mul 2 x) (add x x)` identity `gauss_lemma.rs`/
`parity.rs` already duplicate — needed `mul_comm` as an extra and was
UNSAFE by the same argument as `neg_mul` (ADR-1586 §3). That was wrong, and
I caught it before committing by checking rather than trusting my own
analysis: `target_gauss_lemma_two_mul_eq_add`/`target_parity_mul_two_eq_
add_self` already prove this exact identity is reachable from the DEFAULT
set alone — `succ_mul` unfolds `mul 2 x` to `add (mul 1 x) x` then
`add (mul 0 x) x`, `zero_mul` clears the inner product, `zero_add` clears
the result, no `mul_comm` needed at all. The hand proof's OWN citation path
(`mul_comm` then `zero_add`) is not evidence of what the producer needs —
it can find an entirely different, safe path to the same statement. Landed
as the 11th ℕ retirement once actually tested (see landed-changes below). A
fourth site (`fermat_number_mirrors.rs`) has a similarly-named helper not
yet checked for the same shape — left for a future lane.

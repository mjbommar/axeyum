## Follow-on: discharging the seven `planned` rows is BLOCKED

Investigated 2026-08-01 and deliberately not attempted. The blocker is real and
must be cleared before any discharge lands:

1. **The seven rows are live.** `lt_trans` is consumed by
   `crates/axeyum-solver/src/reconstruct/arithmetic.rs:4036` and `:4161`
   (`ctx.kernel.const_(ctx.arith.lt_trans, vec![])`) for strict-`<` cycle
   refutations. These are not dead declarations.
2. **Discharge changes the exported Lean module.** `Declaration::Theorem`
   renders differently from `Declaration::Axiom`
   (`crates/axeyum-lean-kernel/src/lean_pp.rs:80` vs `:99`, `:486` vs `:519`),
   so a discharged row emits `theorem name : ty := <proof>` where it previously
   emitted `axiom name : ty`. Official Lean must then accept the proof term.
3. **That gate cannot run here.** Neither `lean` nor `elan` is installed, so the
   70/70 `AXEYUM_REQUIRE_LEAN=1` crosscheck is unrunnable locally. Landing a
   prelude change whose validating gate cannot be executed is precisely the
   conservative-slicing violation CLAUDE.md's working stance forbids.
4. **Ordering constraint.** `lt_trans` is declared at `arith_prelude.rs:282`,
   *before* its own dependencies `lt_of_lt_of_le` (`:288`) and `le_of_lt`
   (`:308`). Discharge requires reordering `build_arith_prelude`.
5. **Count coupling.** Removing any axiom breaks four hardcoded checks in
   `scripts/gen-lean-axiom-ledger.py` (`EXPECTED_COUNTS` at `:29`, the 65-row
   assertions at `:118`/`:195`, the `expected_counts` message at `:179`) plus two
   in `scripts/tests/test_lean_axiom_ledger.py` (`:38`, `:43`). Coordinated edit,
   not a one-liner.

**Prerequisite for the discharge slice:** a runnable official-Lean gate
(`elan` + pinned toolchain), then discharge **one** row first — `real::lt_trans`
is the smallest, a two-step term
`fun x y z h1 h2 => lt_of_lt_of_le x y z h1 (le_of_lt y z h2)` — and confirm the
gate still reports 70/70 before touching the other six.

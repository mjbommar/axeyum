## What

Establish that subprocess-invoked kissat/CaDiCaL over a DIMACS-in / proof-out boundary is an
*untrusted conquer engine*, permitted and fenced.

## Files touched

- `docs/research/09-decisions/` (new ADR)

## Exit criteria

- ADR accepted with the fence written explicitly: search-amplifier role only; the native core remains
  the default and the only in-build engine; competitive measurements against the external engines
  continue so the demotion path stays honest

## Notes and traps

The argument: (a) no linking, so the default build stays C/C++-free *literally*; (b) trust never
transfers -- UNSAT requires a natively checked proof, SAT requires native model replay; (c) ADR-0002's
demotion narrative is about *trusted* reliance on Z3, and this adds none; (d) two accepted precedents
exist -- `docs/research/03-architecture/gpu-accelerated-untrusted-search.md` slots untrusted search
engines into the identity, and `axeyum-bench/examples/cnf_core_bench.rs` already shells kissat.

The identity sentence -- untrusted fast search, trusted small checking -- **licenses this**. Say so.

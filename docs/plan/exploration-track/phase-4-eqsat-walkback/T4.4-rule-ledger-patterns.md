## What

A side table `reason -> RuleInstance { rule_id, subst, lhs, rhs }` owned by the driver, plus
pattern-form `(Pattern, PatternRhs, RewriteRuleId)` triples for a starter subset of syntactic bool/BV
identities.

## Files touched

- new module in `axeyum-rewrite` (patterns keyed by existing `RewriteRuleId` consts)
- per-rule differential tests

## Exit criteria

- Every pattern rule id exists in `default_manifest()`
- A differential test per rule pins pattern-form equal to procedural-canonicalizer output
- The `Preservation::Denotation`-only gate is enforced by construction

## Notes and traps

**Dual representations are two sources of truth.** The per-rule differential test is mandatory --
this is exactly the generator-blind-spot class documented at `a946f925` and `ba0d9149`.

The reason-space is the trap: `Edge::Input(u32)` means "SAT literal" to CDCL(T) consumers and would
mean "rule instance" here. One graph, one reason-space owner -- the driver owns its own `EGraph`, or
the ledger is graph-scoped.

Skip conditional and const-folding rules initially; those need a procedural applier over `AppMatch`.

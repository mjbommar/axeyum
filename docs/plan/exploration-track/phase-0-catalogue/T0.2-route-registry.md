## What

Add `crates/axeyum-solver/src/route_registry.rs` holding a `RouteMeta` record for each of the ~45
route labels, populated by reading each dispatch site. This is the single source of truth from which
the JSON artifact is generated -- the `trust_ledger_markdown` pattern (`trust.rs:343-387`).

Fields: `label`, `phase`, `kind`, `order_index`, `requires`/`forbids` feature masks, named opaque
`probes`, `config_gates`, `dynamic_gates`, `verdicts`, `sat_transfer`, `unsat_transfer`, `walk_back`,
`trust_ids`, `source_fragments`, `target`, `reference`.

## Files touched

- new `crates/axeyum-solver/src/route_registry.rs`
- `crates/axeyum-solver/src/lib.rs` (module export)
- new coverage unit test

## Exit criteria

- Every literal passed to a `record_*` call in `auto.rs` appears in `ALL_ROUTES`
- Every `ALL_ROUTES` entry is used
- `cargo test -p axeyum-solver --lib` plus the full pre-merge gate set green

## Notes and traps

Do not hand-transcribe 8,616 lines into JSON -- that is the top rot risk. The eventual coupling is
to make recorder call sites take their label from the registry const so the compiler enforces
coverage; the unit test is the interim measure.

Keep `probes` and `dynamic_gates` as *named opaque references*. `blast_bv2nat_linear` and
`reduction_shrinks_encoding` must not be re-encoded as data.

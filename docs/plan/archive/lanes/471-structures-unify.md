2. **`Complex.commRingS : AlgS.CommRing`**, built on the identical pattern
   (`complex/algebra_instance.rs`), wired into `complex.rs`'s hand-
   maintained `STEPS` table right after `declare_ring_laws`.
   `Complex.mul_one`/`Complex.left_distrib` are stated in the identical
   right/left forms `CReal`'s are (confirmed by reading `declare_ring_

   `equivTrans` derivations `creal/algebra_instance.rs` uses. Evaluation
   test: projecting `mulComm` off `Complex.commRingS` is `def_eq` to
   `Complex.mul_comm`'s own type at free `a, b`. `complex::` sweep: 56/56.
3. **`Alg.ringMulZero`/`Alg.sub_self` made DERIVED theorems**, reached from
   `AlgS.mul_zero`/`AlgS.sub_self` via `AlgS.Ring.ofAlg` (the reduction
   ADR-1588 §2 established: an `ofAlg`-projected value's fields reduce,
   by iota, to exactly the source `Alg` record's own selectors, so the
   `AlgS` theorem's inferred type at `ofAlg R` reduces to precisely the
   `Eq`-flavored statement). Both stated `ty`s are UNCHANGED; measured via
   `kernel_declaration_projection`'s `canonical_type` column against a
   `lane-snapshot.sh 80b04333a` build: **byte-identical** for both
   theorems, footprint still 0 both times. `Alg.neg_neg` is NOT derived --
   it is stated over `Alg.Group`, but `AlgS` has no Group-level generic
   theorem (only Ring-level `mul_zero`/`neg_neg`/`sub_self`), so there is
   nothing matching-scope to derive from; a real structural mismatch,
   reported rather than forced. **Derivation direction**: `Alg` (Eq-based)
   is derivable from `AlgS` (setoid-based) wherever the record SCOPE
   matches; the reverse is not possible in general (a setoid's `equiv` is
   arbitrary, with no `Eq`-form to route a derivation through).
   `rat_prelude::algebra_ext::`/`algebra_instances::` sweep: 30/30,
   including the retirement-match tests (`retirement_rat_sub_self` etc.,
   still passing against the now-derived proofs).
4. **`AlgS.mul_neg_one`/`AlgS.add_left_cancel`**, two more generic
   theorems over `AlgS.Ring`/`AlgS.Group`, each instantiated at Int (via
   `ofAlg`), `CReal`, and `Complex`. `AlgS.add_left_cancel(AlgS.Group.
   ofAlg(Int.addGroup))` closed over `(a,b,c)` IS `def_eq` to `Int.
   add_left_cancel`'s own type -- the same carrier theorem `Alg.
   mul_left_cancel` already retired to (ADR-1587), now reached from the
   setoid spine too. `CReal`/`Complex` have no named carrier theorem for
   either (`mul_neg_one_eq_neg` in `creal/alternating.rs` is a private
   Rust proof-term helper, never a kernel declaration -- the same shape
   ADR-1587 found for `int_prelude/gcd.rs`'s `neg_neg`), so both are
   well-typedness-only there, via `AlgS.CommRing.toRingS` for
   `mul_neg_one` and a new `#[cfg(test)]`-gated term-builder,
   `ring_s_additive_group_value` (builds an `AlgS.Group` value from a
   `Ring` one, deriving `identL`/`invL` from `addComm`+`addZero`/`negAdd`),
   for `add_left_cancel`.

genuinely has no non-test consumer today.

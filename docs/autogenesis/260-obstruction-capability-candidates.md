The 20 obstruction families now divide into 9 with an explicitly candidate

## Boundary

A candidate entity is not an operation, a producer, a proof plan, or admission
authority. It merely turns a recurring, observed failure shape into a named
research obligation. The generator reads candidate status from the overlay;
the validator rejects an output that says an overlay candidate is active or
absent.

This is the practical bridge between bottom-up decline data and top-down work
selection: the next code investment can be chosen because it removes a
measured cluster, while the kernel and ordinary evidence checks still decide
whether any resulting proof is durable.

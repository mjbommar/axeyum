# 01 — PyO3 / maturin: the binding crate and its gate

Status: plan, 2026-08-24. Measured basis:
[`studies/pyo3-maturin-feasibility.md`](studies/pyo3-maturin-feasibility.md).

## What this plan delivers

A workspace member `crates/axeyum-py` that compiles to `axeyum._native`, a pure
Python package `python/axeyum/`, a root `pyproject.toml` that `uv` and `maturin`
both understand, generated type stubs with a drift gate, and one aggregate gate
`just py-check` that prints how many tests it ran. **No API beyond a version
probe and one `smt.solve` smoke path** — the surface is plan 02's job. This
plan is the scaffolding, and it is done when a fresh clone can
`uv sync && uv run maturin develop && uv run pytest` and see a nonzero count.

## Decisions, each with the measurement that made it

| decision | why (measured 2026-08-24) |
|---|---|
| PyO3 `0.29`, exact-pinned | compiles under `unsafe_code = "deny"` + clippy pedantic `-D warnings` (probe exit 0); MSRV 1.83 ≤ workspace 1.88 |
| `abi3-py312` | one wheel per platform for 3.12–3.14; maturin 1.15.0 built `cp312-abi3-manylinux_2_34` in one command; free-threaded 3.14t needs a separate non-abi3 wheel later, not now |
| `pyo3/extension-module` **only** via `[tool.maturin] features` | as a Cargo default it breaks `cargo test --workspace` (cdylib cannot link Python symbols); glaurung already does this right |
| no `libpython` link | `ldd` on the built `.so`: none. The default build stays free of C/C++ (ADR-0002); the crate is a leaf like `axeyum-wasm` (ADR-0017) |
| `#[pymodule(gil_used = true)]` for v1 | PyO3 0.28+ *defaults* to declaring thread-safety; we have not audited `Sync` on mutable classes. Costs a `RuntimeWarning` on free-threaded builds only, which we do not ship yet |
| root `pyproject.toml`, `manifest-path` to the crate | maturin prefers crate-local config but a root project is what `uv sync` and the agent extra need; one Python packaging story, not two |
| stubs generated by introspection, drift-gated | glaurung's `tools/gen_native_stub.py` exists because a hand-written stub produced 417 bogus diagnostics; port it rather than re-learn it |

## Layout

```
pyproject.toml                        # [build-system] maturin; [tool.maturin] manifest-path, module-name, python-source
uv.lock
crates/axeyum-py/
  Cargo.toml                          # [lib] crate-type = ["cdylib", "rlib"]; pyo3 = "=0.29.2" features ["abi3-py312"]
  src/lib.rs                          # #[pymodule] fn _native — registration only, one line per submodule
  src/convert.rs                      # IntoPyObject / FromPyObject impls for Value, ids, errors
  src/error.rs                        # AxeyumError hierarchy (create_exception!)
  src/smt.rs                          # plan 02 fills these; plan 01 ships smt::version + smt::solve only
python/axeyum/
  __init__.py                         # re-exports; sets __version__ from _native
  py.typed
  _native/__init__.pyi                # GENERATED
  _native/<sub>.pyi                   # GENERATED, one per submodule
python/tests/
  conftest.py
  test_import.py                      # version(), module attrs match stub
  test_smt_smoke.py                   # sat / unsat / unknown as values; replay() True on sat
tools/gen_native_stub.py              # ported; `--check` exits 1 on drift AND on zero stubs compared
```

`crates/axeyum-py/Cargo.toml` depends on `axeyum-solver` with
`default-features = false, features = ["full"]` — the front door needs `full`,
and it is pure Rust (the C/C++ `z3` backend is a separate feature and stays
off). `axeyum-cas`, `axeyum-lean-kernel`, `axeyum-lean-import`, `axeyum-ir`,
`axeyum-smtlib`, `axeyum-cnf` are added by plan 02 as each submodule lands.

## Slices

Each slice is one commit, gated, in order. A slice that fails its gate is not
landed and the next slice does not start.

### S1 — crate, pyproject, package, version probe

- `crates/axeyum-py` with `_native.version() -> str`; add to workspace
  `members`. `[lints] workspace = true`.
- root `pyproject.toml`: `name = "axeyum"`, `requires-python = ">=3.12"`,
  `dynamic = ["version"]`, `[tool.maturin] manifest-path`, `module-name =
  "axeyum._native"`, `python-source = "python"`, `features =
  ["pyo3/extension-module"]`; `[dependency-groups] dev = ["maturin>=1.15,<2",
  "pytest>=8", "ruff", "ty"]`. `[build-system].requires` provisions the PEP
  517 backend, not a runnable `maturin` — the dev group is what puts it on
  `PATH` (glaurung hit exactly this in CI).
- `python/axeyum/__init__.py`, `py.typed`.
- Gate: `cargo clippy -p axeyum-py --all-targets -- -D warnings` **on the default
  toolchain as well as `+stable`** — the default here is nightly, whose newer
  lints reach into every crate the binding pulls in (a `collapsible_match` in
  `axeyum-solver` made this gate red on nightly while stable was green,
  2026-08-24);
  `cargo test --workspace` still links (no `extension-module` default);
  `uv run maturin develop`; `python -c "import axeyum; print(axeyum.__version__)"`.

### S2 — error hierarchy and value conversion

- `AxeyumError(Exception)` root; `SmtLibParseError`, `KernelError`
  (with typed subclasses added in plan 02), `BudgetExceeded`. **`unknown`
  and `declined` are never exceptions.**
- `convert.rs`: `Value::Bool → bool`, `Value::Bv{width,value} → int` plus a
  `BvValue(int)` subclass carrying `.width`, `Value::WideBv → int` (arbitrary
  precision is free on the Python side), integer/rational/real values as
  `int` / `fractions.Fraction` / whatever plan 02's inventory says the IR
  carries. Every conversion has a round-trip test.
- Gate: pytest count > 0; ruff; `ty` (or mypy) clean on `python/`.

### S3 — `smt.solve` smoke path and replay

- `axeyum.smt.solve(script: str, *, timeout_ms: int = 10_000) -> Outcome`
  over `axeyum_solver::solve_smtlib`; `Outcome` is `#[pyclass(frozen)]` with
  `status`, `logic`, `expected_status`, `model` (dict), `detail`;
  `Outcome.replay() -> bool` over the solver's canonical model check.
- Long call runs under `py.detach()`.
- Tests: one `sat` (replay `True`), one `unsat`, one `unknown` produced by a
  1 ms timeout on a hard instance (**a value, not an exception**), one parse
  error (an exception), and a differential: the same five corpus files
  through `target/release/examples/smtcomp_cli` and through `smt.solve` agree.
- Gate: as S2, plus the differential.

### S4 — typed stubs and the two drift gates

**Landed as introspection stubs; replaced by TYPED stubs 2026-08-24 (goal 10,
slice Q5).** The original design is kept below the line because the reason it
was replaced is the interesting part.

Today the stubs are generated **from the Rust signatures** by
`pyo3-stub-gen` 0.23 (PyO3 `>=0.27,<0.30`, so the `=0.29.2` pin fits):

```sh
cargo run -p axeyum-py --features stub-gen --bin stub_gen
```

- `stub-gen` is a Cargo feature that is **off by default and absent from
  `[tool.maturin] features`**. `pyo3-stub-gen` works by `inventory::submit!`ing
  a record per class, method and function into a link section walked at run
  time; those records are static data the extension itself never reads, so the
  wheel is built without them and the generator links the same library with the
  feature on. Every annotation is written
  `#[cfg_attr(feature = "stub-gen", pyo3_stub_gen::derive::gen_stub_*)]`, so the
  default build does not even resolve the path.
- The stubs are a **package** — `_native/__init__.pyi`, `_native/cas/__init__.pyi`,
  `_native/cas/certify/sos/__init__.pyi`, one directory per PyO3 submodule.
  That is not cosmetic: a flat `_native/cas.pyi` is a *module* and can therefore
  have no `certify` member, which is exactly why `axeyum._native.cas.certify`
  and `axeyum._native.kernel.identity` were unresolved imports under `ty` while
  both exist at run time. `[tool.maturin] include` uses `**` to match.
- Types PyO3 has no Rust type for are named by transparent wrappers in
  `crates/axeyum-py/src/stub_types.rs` (`PyFraction` → `fractions.Fraction`,
  `PyBigInt` → `int`, `PySequence<T>` → `typing.Sequence[T]`,
  `PyBorrowedList<T>` → `list[T]`, `PyFrozenSetOf<T>` → `frozenset[T]`) and by
  `RationalLike` / `NameLike` next to the code that reads them. A wrapper puts
  the claim in the Rust signature where the compiler sees it; a stub *override*
  would be a second statement of the type, written in a string, checked by
  nothing.
- Exceptions and module constants reach Python through runtime calls
  (`create_exception!`, `module.add("MAX_BV_WIDTH", ...)`), so no item exists
  for a macro to sit on. They are submitted from feature-gated blocks —
  `crate::stub_info::stub_exception!` and `pyo3_stub_gen::module_variable!` —
  which is also how `Declined.reason` and `KernelError.variant/fields/names`
  get declared at all: those are attached with `setattr` at the **raise** site
  and exist on no class.

Two gates, deliberately separate, so a type improvement cannot mask a name
regression:

| gate | compares | prints |
|---|---|---|
| `tools/gen_native_stub.py --check` | the built `.so` against the stubs: names, parameter names, arity. **Annotations ignored.** | `STUBS\|modules=M\|symbols=S\|aliases=A\|synthesised_dunders=D` |
| `tools/check_stub_types.py` | every `typing.Any` in the stubs against `python/axeyum/_native/ANY_ALLOWLIST.txt` | `STUB_TYPES\|params=P\|typed=T\|any=A\|allowlisted=L\|return_any=R` |

plus `python -m mypy.stubtest axeyum._native` (see `just py-check` for the exact
flags), which is the only checker here that compares stubs to the runtime **as
types** — `ty` reads the stubs and believes them.

`gen_native_stub.py` no longer generates anything. Its three deliberately weak
comparisons are `__new__` (PyO3 puts the real `#[new]` signature on the CLASS's
`__text_signature__`), every other dunder (CPython slot wrappers name their
argument `value`/`key`, never the Rust name, and are positional-only: arity
only), and aliases (`ir.bv.lower_terms_py` **is** `ir.bv.lower_terms`, one
object under two names).

---

Original S4 (superseded):

- Port `tools/gen_native_stub.py` (introspection of the built module,
  `__text_signature__` → parameter names and defaults, `Any` for types —
  sound, never inventive). `--check` must exit 1 on drift **and** on zero
  stubs compared.
- `python/tests/test_native_stub_current.py` runs the generator into a temp
  dir and compares byte-for-byte.
- Gate: `uv run python tools/gen_native_stub.py --check` prints

### S5 — `just py-check` and CI wiring

- `justfile` recipe `py-check`: `maturin develop` → `pytest python/tests
  -q` (assert nonzero collected via `-p no:cacheprovider` and a conftest
  hook that fails the session if `collected == 0`) → stub `--check` → `ruff
  check` → `ruff format --check`. Each step prints its count.
- `scripts/check.sh` gains the same steps **conditional on `uv` being
  present**, and prints `py-check: SKIPPED (no uv)` otherwise — skipped, never
  passed. Add `uv` to the capability map in
  `docs/contributor-guide/fleet-hosts.md`.
- CI job `python` on 3.12 / 3.13 / 3.14; `cargo deny check` reviewed for the
  new dependency tree (MIT/Apache-2.0 throughout — confirm, do not assume).
- `cargo build --target wasm32-unknown-unknown -p axeyum-solver` unaffected
  (the binding crate is not a dependency of anything).

### S6 — ADR and docs

- ADR: *the Python surface is a projection; submodule = trust tier; no
  admission authority; `unknown`/`declined` are values.* Regenerate the ADR
  index with `scripts/gen-adr-index.py`.
- `docs/user-guide/python.md`: install, `maturin develop`, `TMPDIR`, the
  tier table. CLAUDE.md commands block gains three lines (`uv sync`, `maturin
  develop`, `just py-check`) and the `TMPDIR` note.

## Exit criteria for the plan

- Fresh clone on a host with `uv`: `uv sync --locked --dev && uv run maturin
  develop && just py-check` passes and prints `pytest: N passed` with N ≥ 12,
  `STUBS|compared=M` with M ≥ 2.
- `just check` on a host **without** `uv` still passes and prints the
  `SKIPPED` line — the Rust gates are unchanged.
- `cargo test --workspace --all-features`, clippy, `cargo doc`, `cargo deny`,
  and the wasm build all pass with the new member present.
- The ADR is indexed; `scripts/check-links.sh` passes over this folder.

## Hazards specific to this repository

- **The prelude cache is process-global** (`prelude_cache.rs`, `OnceLock`
  statics). Plan 02 must hand out a clone (`Kernel.fork()`) before any
  mutation; noted here because the binding crate's *design* must not assume a
  fresh kernel per call.
- **Memory.** In-process solving makes the Python process the OOM victim.
  `solve()` exposes the solver's own limits as kwargs; unbounded *search* from
  an agent belongs in a subprocess under cgroup caps (plan 03).
- **Mutation testing in the shared worktree** breaks sibling lanes' builds —
  do it in a `scripts/lane-snapshot.sh` tree, or via
  `scripts/tests/mutation_controls.py`.
- **Two lanes, one `justfile` / `check.sh`.** Both are shared append points.
  Before `git add`, `git diff` each and confirm every hunk is yours;
  commit through `scripts/lane-commit.sh`.

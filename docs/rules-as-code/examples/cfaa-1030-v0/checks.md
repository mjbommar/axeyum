# CFAA V0 Checks

Each check is an SMT-LIB obligation generated by `rules_ir.py` from
[`rules.json`](rules.json) into [`smt2/`](smt2/). Regenerate with:

```sh
python3 scripts/uscode_lift.py \
  docs/rules-as-code/uscode/sources/USCODE-2023-title18-partI-chap47-sec1030.htm \
  docs/rules-as-code/uscode/lifted/usc-t18-s1030.json
python3 scripts/rules_ir.py docs/rules-as-code/examples/cfaa-1030-v0/rules.json
```

and check with:

```sh
cargo test -p axeyum-solver --features full --test rules_as_code_examples cfaa_1030
cargo run -q -p axeyum-solver --features full --example rules_check -- \
  docs/rules-as-code/examples/cfaa-1030-v0/smt2/*.smt2
```

An `unsat` check passes only when `produce_evidence` returns certified evidence
and `Evidence::check` re-derives it against the parsed obligation. A `sat`
check passes only when the returned model replays against the obligation.

| Check | Expected | Provisions | Obligation |
|---|---|---|---|
| `penalty-coverage-unsat` | unsat | (c)(2)–(c)(4) | No modeled clause applies. |
| `penalty-overlap-c2b-c2c-sat` | sat | (c)(2)(B), (C) | Both (c)(2)(B) and (c)(2)(C) apply. |
| `value-threshold-mismatch-sat` | sat | (c)(2)(B)(iii), (c)(4)(A)(i)(I) | One amount meets the loss test and fails the value test. |
| `civil-gate-within-felony-factors-unsat` | unsat | (g), (c)(4)(A)(i) | The civil gate holds and no (c)(4)(A)(i) factor does. |
| `civil-gate-excludes-factor-vi-sat` | sat | (g), (c)(4)(A)(i)(VI), (c)(4)(B) | An (a)(5)(A) offense has a felony factor and the civil gate is closed. |
| `max-term-monotone-unsat` | unsat | (c)(2)–(c)(4) | Two fact patterns, the second at least as aggravated, and the second has the lower maximum. |
| `implementation-equivalence-unsat` | unsat | (c)(2)–(c)(4) | The decision table and the model disagree. |
| `buggy-implementation-counterexample-sat` | sat | (c)(2)(B)(iii) | The `>=` decision table and the model disagree. |

## Gates before the solver

`rules_ir.py` fails, and emits nothing, when any of these does not hold:

- every predicate's anchor phrase occurs verbatim in its provision;
- every integer literal in a predicate is a quantity the lifter extracted from
  that provision, and a comparison uses the comparator the text states;
- every dependency between predicates on different provisions is justified by
  outline structure, a resolved cross-reference, a defined-term use, or an
  explicit declared justification (recorded as such in `compiled.json`);
- every internal cross-reference leaving a modeled provision is consumed by the
  model or listed as out of scope with a reason.

Four single-edit mutations of `rules.json` that these gates reject:

| Mutation | Rejection |
|---|---|
| `(> info_value_usd 5000)` → `(>= …)` | `compares with >= 5000, but /c/2/B/iii states ['>'] 5000` |
| `(>= computers_damaged 10)` → `5` | `literal 5 is not a quantity stated in /c/4/A/i/VI` |
| add `harm_VI` to `civil_factor_I_V` | `uses harm_VI (/c/4/A/i/VI) with no textual justification` |
| `c2A_max` `1` → `2` | `literal 2 is not a quantity stated in /c/2/A` |

A semantic error inside one provision passes these gates: dropping
`(not prior_conviction)` from `c4A_applies` is anchored, literal-free, and
structurally justified. The validator's sweep rejects it at the first row where
the clause sets differ (`rule model clauses ['(c)(4)(A)', '(c)(4)(C)'] !=
statute reading ['(c)(4)(C)']`). The solver's equivalence check would not,
because (c)(4)(C)'s 20 years masks the extra clause in the maximum; the sweep
compares clause sets for that reason.

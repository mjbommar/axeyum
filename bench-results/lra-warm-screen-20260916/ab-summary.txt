THE MECHANISM, AND THE PREDICTION IT CONFIRMS
---------------------------------------------

    arm         rows `built`   cubes answered   cold tableaux left   cold_restarts
    on                    71           38,344                    0               0
    screened              51           32,742                3,871               0
    off                    -                -               33,158               -

  * `cold_restarts = 0` in both treatment arms. That is the tripwire: a warm
    basis quietly being rebuilt gives identical verdicts, identical churn counts,
    and differs only in the clock, so nothing else here could see it.
  * The screen REFUSED 20 of the 71 rows `on` kept a basis on, and opened on
    **0** that `on` did not. The second number is the one that would indicate a
    bug; it is zero.
  * 51 < 71, both nonzero: criterion 5 is met by construction of the run rather
    than by assertion.

**THE ADMITTED SET WAS PREDICTED EXACTLY, NOT JUST ITS SIZE.** Section 1.4
derived, from ADR-2125's committed sizing -- a different lane, a different
binary, a different day -- that 51 of the pinned 200 sit at or above 64 builds
and that the screen would admit those. Measured:

    predicted from ADR-2125's sizing (builds >= 64):   51
    screened arm built a decider on:                   51
    screened arm answered >=1 cube warm on:            51
      predicted but NOT built:                          0
      built but NOT predicted:                          0

Same count and the SAME SET. That is the sizing axis being reproducible enough
to route on, which is a stronger statement than the histogram alone supports and
is the reason the threshold could be chosen before the code existed.

NOTE ON THE `warm_cube_build` COLUMN IN THIS DATA
--------------------------------------------------
`axeyum.v1` predates the `below-screen` token, so in these captures a screened
row that never crossed the threshold renders `warm_cube_build=off` -- the same
token a DISABLED lever renders. That defect is fixed in the tree but not in the
measured binary, and swapping a binary mid-run is the one thing an A/B cannot
survive. Every analysis here therefore reads the screen's refusals as
`c_warm_checks = 0` with a nonzero `a_cold_builds`, which is unambiguous in v1's
own data.
